# SDD — Roadmap de Implementación
## Sistema de Gestión de Kiosco

---

## 1. Objetivo del Roadmap

Definir la ruta de implementación del **Sistema de Gestión de Kiosco**, estableciendo un orden progresivo para el análisis, diseño, desarrollo, pruebas e integración de las diferentes funcionalidades del sistema.

El proyecto será desarrollado de manera incremental bajo una **Arquitectura Hexagonal (Ports and Adapters)**, incorporando funcionalidades por etapas. Cada etapa deberá ser validada mediante pruebas automatizadas (unitarias, de controladores e integración) antes de avanzar hacia funcionalidades que dependan de ella.

El objetivo es construir el sistema progresivamente, manteniendo en todo momento un código organizado, desacoplado, funcional y verificable.

---

## 2. Resumen Tecnológico Base

### 2.1 Frontend
* **Tecnologías:**
  * Next.js
  * TypeScript
  * React
  * Tailwind CSS (o librería visual a definir)
  * Consumo de API REST del backend
  * Firebase Auth SDK para login
  * Manejo de sesión mediante **Firebase ID Token** enviado al backend (Header Authorization Bearer)

### 2.2 Backend
* **Tecnologías:**
  * C# en .NET 8 o superior (ASP.NET Core Web API)
  * Entity Framework Core & Npgsql para PostgreSQL
  * Firebase Admin SDK (para validación de tokens en backend)
  * Firebase Storage SDK o integración mediante Google Cloud Storage compatible
  * Swagger / OpenAPI para documentación
  * FluentValidation para la capa de validación
  * Serilog para logging estructurado
  * Librería para generación de Excel (ClosedXML o EPPlus)

### 2.3 Base de Datos
* **Tecnología:** PostgreSQL
* **Identificadores:** `int` PK autoincremental (`GENERATED BY DEFAULT AS IDENTITY`)

### 2.4 Autenticación
* **Tecnología:** Firebase Auth
* **Responsabilidades:** Login, recuperación de contraseña, gestión de identidad externa, emisión de Firebase ID Token y eventual verificación de email.
* **Regla:** Firebase Auth no reemplaza el modelo de usuarios interno del sistema.

### 2.5 Autorización Interna
* La autorización real del sistema se manejará en **PostgreSQL** y **ASP.NET Core**.
* **Flujo conceptual:**
  ```text
  Firebase UID → Usuario interno → Roles → Permisos → Autorización
  ```

## 22. Ciclo incremental

El desarrollo no deberá realizarse implementando todo el sistema primero y probándolo al final.

Cada funcionalidad deberá seguir un ciclo:

```text
Requerimiento
      ↓
Diseño
      ↓
Implementación
      ↓
Pruebas
      ↓
Corrección
      ↓
Integración
      ↓
Regresión
      ↓
Documentación
```

Este enfoque permitirá que el sistema evolucione progresivamente y que cada modificación importante quede validada.
